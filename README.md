# مصنع البرمجيات

مصنع وكلاء يعملون **بالتتابع**، لكل مرحلة وكيلها، ومبني على مهارات Matt Pocock:

```
الاكتشاف معك ← لكل مهمة: كاتب الاختبارات ← المنفذ ← الفاحص ← المدقق ← المراجع ← المراجعة النهائية ← تحسين المصنع
```

يعمل في مسارين: **مشروع جديد** تبنيه من الصفر، أو **مشروع موجود** تضيف إليه ميزة أو تصلح فيه أخطاء.

هذا الملف يشرح التشغيل فقط. شرح الوكلاء والبوابات والدروس بالتفصيل في [docs/reference.md](docs/reference.md).

---

## المتطلبات

| الأداة | لماذا |
|---|---|
| **Claude Code** (سطر الأوامر `claude`) | يشغّل الوكلاء. يجب أن يتيح حسابك مودلات Opus وSonnet وHaiku |
| **Node.js 18 أو أحدث** | سكربتات المصنع والحارس وحساب التوكنز |
| **git** | المصنع يحفظ كل خطوة في commit ويتحقق من التغييرات عبر git |
| اتصال بالإنترنت (اختياري) | لتحديث مهارات Matt ولخط الداشبورد. بدونه يعمل المصنع بالنسخة المثبتة |

## ما الذي تنسخه

انسخ هذه الملفات من مجلد المصنع إلى **جذر** مشروعك:

| ما تنسخه | ما فيه |
|---|---|
| `.claude/agents/` | الوكلاء الأحد عشر |
| `.claude/skills/` | مهارات Matt Pocock، وأوامر `/factory` و`/discovery` و`/bug` |
| `.claude/settings.json` | الحارس وحساب التوكنز، على شكل hooks |
| `factory/` | السكربتات، والإعدادات، والداشبورد، وبروتوكول المراجعة |
| `CLAUDE.md` | دليل قصير يقرؤه كل وكيل |

إن كان المصنع قد عمل على مشروع سابق، يمكنك نسخ `factory/lessons/` أيضًا، فيبدأ الوكلاء بالدروس التي تعلّموها هناك.

## التشغيل على مشروع جديد

**1. جهّز المجلد**

```bash
mkdir my-app && cd my-app && git init
```

```bash
cp -r /path/to/software-factory/{.claude,factory,CLAUDE.md} .
```

في PowerShell على Windows:

```powershell
Copy-Item -Recurse C:\path\to\software-factory\.claude, C:\path\to\software-factory\factory, C:\path\to\software-factory\CLAUDE.md .
```

```bash
git add -A && git commit -m "Add software factory"
```

**2. جلسة الاكتشاف** (أنت حاضر طوال الوقت):

```bash
claude --agent discovery
```

- عند أول تشغيل يسألك Claude Code إن كنت تثق بإعدادات المشروع. **وافق**، وإلا لن يعمل الحارس ولا حساب التوكنز.
- اكتب فكرتك، وأجب على جولات الأسئلة. لكل سؤال إجابة مقترحة، و"نعم" تعني قبولها.
- قد تقترح الجلسة نموذجًا تجريبيًا أو بحثًا عندما لا يُحسم سؤال بالكلام.
- في النهاية تكتب المواصفات مقسمة إلى **ميزات**، ثم **مهام**، وتراجعها معك حتى توافق.
- **في مشروع جديد لا توجد أوامر فحص بعد:** الجلسة تحددها (مثل `npm test`)، والمهمة الأولى تبني أدوات الاختبار نفسها.
- تنتهي الجلسة حين يظهر `plan-ready: OK`.

**3. البناء** في جلسة **جديدة**:

```bash
claude --agent orchestrator
```

الموجّه يشغّل الوكلاء واحدًا بعد الآخر، ويكتب لك سطرًا عن كل خطوة.

**4. شاهد اللوحة:** افتح `factory/dashboard.html` في المتصفح مباشرة، فلا يحتاج سيرفر.

```bash
start factory/dashboard.html
```

(على Mac: `open`، وعلى Linux: `xdg-open`.)

**5. متى يحتاجك المصنع؟** يتوقف ويسألك في هذه الحالات فقط:

| الحالة | ماذا تفعل |
|---|---|
| مهمة فشلت 3 محاولات | تختار: إعادة المحاولة، أو تخطّي المهمة، أو تعديل تصفه |
| وكيل خالف صلاحياته | تراجع التغيير وترجعه، ثم تطلب الاستمرار |
| المشخّص يحتاج معلومات عن خطأ | تعطيه ما يطلبه |
| وكيل التحسين يقترح تعديلات على المصنع | تختار ما تقبله منها |

**6. النهاية:** تجد وصف التسليم في `factory/PR.md`. **المصنع لا يدفع إلى git ولا يدمج أبدًا.** راجع الفرع، ثم ادفعه أو ادمجه بنفسك.

## التشغيل على مشروع موجود

### قبل النسخ

**1. ابدأ من فرع نظيف.** المصنع يحفظ commits على الفرع الحالي:

```bash
git status
```

```bash
git switch -c factory/my-feature
```

**2. انسخ الملفات** كما في المشروع الجديد، مع هذه الحالات:

| إن كان عندك | فافعل |
|---|---|
| `.claude/settings.json` | **لا تستبدله.** أضف إليه قسم `hooks` وقائمة `permissions.deny` من ملف المصنع، واحتفظ بإعداداتك |
| `CLAUDE.md` | **لا تستبدله.** أضف محتوى ملف المصنع في آخره |
| وكلاء في `.claude/agents/` بنفس الأسماء | غيّر أسماء وكلائك، أو لا تنسخ الوكيل المتعارض |
| إضافة Matt Pocock مثبتة (plugin) | ستظهر المهارات مرتين، فعطّل الإضافة في هذا المشروع |

### اضبط الفحوص قبل أي شيء

المصنع يشغّل أوامر الفحص بعد **كل** تنفيذ، ويرفض أي نتيجة لا تنجح فيها. لذلك:

**3. ضع أوامر مشروعك الحالية** في `factory/config.json`:

```json
"checks": {
  "typecheck": "npx tsc --noEmit",
  "lint": "npm run lint",
  "test": "npm test"
}
```

**4. تأكد أنها تنجح الآن، قبل أي تعديل.** إن كانت فاشلة من الأساس، فسيرفض المصنع كل تنفيذ. أمامك ثلاثة حلول:
- **أصلحها أولًا.**
- **أو** ضع فقط الفحوص التي تنجح حاليًا.
- **أو** ابدأ بـ"إصلاح الأخطاء فقط" (في الأسفل) وأبلغ عن الفحوص الفاشلة كأخطاء.

**5. حدّد مكان اختبارات القبول وأمر تشغيلها.** `{dir}` يُستبدل بمجلد المهمة:

```json
"acceptance": { "dir": "tests/acceptance", "command": "npx vitest run {dir}" }
```

| بيئة المشروع | مثال للأمر |
|---|---|
| Vitest | `npx vitest run {dir}` |
| Jest | `npx jest {dir}` |
| pytest | `pytest {dir}` |
| Go | `go test ./{dir}/...` |

إن تركتها فارغة، تسألك جلسة الاكتشاف عنها وتملؤها.

```bash
git add -A && git commit -m "Add software factory"
```

### ثم اختر المسار

**أ. إضافة ميزة:**

```bash
claude --agent discovery
```

- **صف الميزة التي تريد إضافتها، وليس المشروع كله.** الجلسة تقرأ الكود الموجود ومصطلحاته وقراراته المعمارية، وتبني المواصفات على ما هو موجود.
- إن لم يكن عندك `GLOSSARY.md`، تبدأ الجلسة واحدًا بالمصطلحات التي تتفقان عليها.
- بعد `plan-ready: OK`، افتح جلسة جديدة:

```bash
claude --agent orchestrator
```

**ب. إصلاح أخطاء فقط** (بلا ميزات جديدة):

```bash
claude --agent orchestrator
```

ثم صف الخطأ للموجّه، أو استخدم:

```
/bug أدخلت 10 و20 فظهر المجموع 01020 بدل 30
```

- المصنع يتخطى الاكتشاف، ويبدأ كل خطأ عند **المشخّص**: يعيد إنتاج الخطأ، ويجد سببه، ويكتب اختبارًا يفشل بسببه.
- بعدها يصلحه المنفذ، ويمر الإصلاح بخط الإنتاج كاملًا.
- **بلا مراجعة نهائية:** لا توجد مواصفات يُقارن بها المشروع.

**النهاية** كما في المشروع الجديد: راجع الفرع، ثم ادمجه بنفسك.

## الأوامر التي ستحتاجها

| الأمر | متى |
|---|---|
| `claude --agent discovery` | بداية مشروع، أو ميزة جديدة |
| `claude --agent orchestrator` | تشغيل البناء، أو متابعته بعد توقف |
| `/bug <وصف الخطأ>` | في أي وقت بعد كتابة الخطة، حتى بعد التسليم |
| `node factory/scripts/factory.mjs status` | حالة المشروع في الطرفية |
| `node factory/scripts/factory.mjs resume 03 retry` | إعادة مهمة متوقفة (أو `skip` لتخطيها) |
| `node factory/scripts/update-skills.mjs check` | هل توجد نسخة أحدث من مهارات Matt؟ |
| `node factory/scripts/factory.mjs init "الاسم" --force` | البدء من جديد. الدروس تبقى |

عادةً لا تحتاج أوامر `factory.mjs` بنفسك، لأن الموجّه يشغّلها نيابة عنك.

## ماذا تحفظ في git

`factory/.gitignore` يستثني ملفات التشغيل التي تتغير مع كل خطوة: `state.json` و`usage.json` و`data.js` و`guard-log.jsonl` و`skills-status.json`.

**احفظ الباقي**، فهو تاريخ المشروع: المواصفات، والمهام، والتقارير، والدروس، ومقترحات التحسين.

## مشاكل شائعة

| المشكلة | السبب والحل |
|---|---|
| اللوحة لا تتحدث، أو التوكنز صفر | الـ hooks لا تعمل. افتح `claude` في المشروع، واكتب `/hooks`، وتأكد من ظهور `PreToolUse` و`SubagentStop` و`Stop`. وتأكد أن `node` موجود في PATH. **بدون الـ hooks لا يعمل الحارس أيضًا** |
| `plan-ready` يرفض | يعرض كل المشاكل دفعة واحدة. الجلسة تصلحها وتعيد المحاولة |
| البوابة الآلية ترفض كل تنفيذ | غالبًا أوامر الفحص فاشلة من الأساس. راجع الخطوة 4 في المشروع الموجود |
| الموجّه يقول "out of sequence" | الحارس منع تشغيل وكيل خارج الترتيب. هذا مقصود: دع الموجّه يكمل الحلقة |
| انقطعت الجلسة في منتصف العمل | شغّل `claude --agent orchestrator` من جديد، فيكمل من حيث توقف |
